# Cell references and extra data: what stands between them and a native layout (nv-rs#952)

Fork-only. The census that decides the order of the move, taken 2026-11-27 on `fork`. Nothing here has moved:
both families (`cell_refs`, id 35; `extra_data`, id 46) are stage 1 (`stage2: false`), objects in guest memory.
The lockfree family's path ([`LOCKFREE-MOVED.md`](LOCKFREE-MOVED.md)) is the template: dual, K1 (moved, guest heap
unchanged, time-slice steps charged with `Engine::typed_charge`), the save check, K2.

## What would move

The extra data of a reference, a cell or an inventory entry:

- the list (`BaseExtraList` / `ExtraDataList`, `0x20` bytes): vtable, chain head (+4), type bitmap (+8, 21 bytes);
- the chain's nodes (`BSExtraData`: vtable, type +4, next +8, payload from +0xc), about 60 classes, each with its own
  payload layout and its own `Create`, constructor, destructor and copy.

The lists are embedded in forms (a reference's at +0x44, a cell's at +0x28), so their guest block is the form's, which
#951 (forms) moves separately; the nodes are separate heap blocks and are the part this ticket can move first.

## Gate 1: every function of the family typed (not met)

About 480 functions that build, read or free nodes are still translations. A node moved to host memory would have
to be built by typed `Create` functions (through `Store::alloc`) and read only by typed accessors, so these come
first: the K1 stub of a node (vtable and type stay for untyped virtual calls; the next and payload move) cannot be
filled by a translated `Create`. Typing them is the porting loop's work (`docs/fork/PORTING-LOOP.md`, one family per
worktree); this ticket does not duplicate it.

## Gate 2: untyped readers (census)

Direct readers of a node's payload or a list's head and bitmap in the built-in extenders, by command, are in
[`EXTENDER-MOVE-INVENTORY.md`](EXTENDER-MOVE-INVENTORY.md), section "extra data" (generated by
`scripts/fork/extender_move_inventory.py`; the four fields are tracked, not yet `moved`). Today it lists about 80
rows: xNVSE's inventory reference walk (`invref.rs`, the type bitmap read for every inventory command), the door,
owner, key, rank and heading commands (`misc_ref.rs`, `misc_ref_more.rs`: payload words read and written after
`GetExtraData`), and JIP LN NVSE's `SetRefExtraData`, mini map and weapon damage commands. Each must reach the node
through the family's typed functions at their exe addresses (the getters and setters of `extra_data::access` and
`setters`, `GetExtraData` `00410220`, `AddExtra` `0040ff60`) before the fields are marked `moved`, when the guard
(`--check`, nv-rs#945) starts failing on the direct reads.

## Order of the move

1. Type the 480 functions above and tick them in the ledger (pipeline).
2. Replace the extenders' direct node reads with calls to the typed accessors; mark the four fields `moved` in the
   generator, so the guard holds the line.
3. Route the family's code through a `Store` (the lockfree `store.rs` pattern), then dual runs over the bench
   scenes.
4. K1 as the default with `typed_charge` for every call by address the moved form does in place (the lists of
   steps found by logging the address of every time-slice step in stage 1 and K1 and aligning them).
5. Save and co-save round trips: extra data is saved (`extra_data::save`, the co-save records of the extenders that
   keep data on references), so unlike the lockfree maps these are real tests, not an argument.
6. K2 only if the step logs allow it (the lockfree K2 does not).

## The node classes' functions that wait for a world (nv-rs#952)

`engine_typed::extra_data::nodes` types the constructors, destructors, `Compare`, `Copy`, `InitItem` and accessors of the node classes. `crates/engine/tests/typed_extra_nodes.rs` runs a differential case of each against its translation, in a world of seeded blocks (`A::Shaped` with `Fill` makes the fields a function walks real; `node_real` leaves the list and array primitives to their translations so a loop that empties a list ends). A function is registered when its case passes.

39 functions are typed but not registered, listed in `nodes::UNVERIFIED`: their cases still stop on both sides alike before any real path runs (a null field, or a container the world does not build) or differ in the calls made (a callee the case does not yet list), so they compared too little.
