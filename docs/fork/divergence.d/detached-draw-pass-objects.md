### The pass objects and Group C's entries are in the detached draw's value packet
- Files: `crates/engine-core/src/typed/leaf.rs`, `crates/engine-typed/src/draw/lighting30.rs`, `crates/engine-typed/src/draw/passes.rs`, `crates/engine-typed/src/draw/skin.rs`, `crates/engine-typed/src/draw/speedtree.rs`, `crates/engine-typed/src/render/pass.rs`, `crates/engine-typed/src/shader/textures.rs`, `crates/engine-bs/src/units/bsshader/lighting30shader.rs`, `crates/engine-fallout-unplaced-b/src/units/unplaced/run_00c048b0.rs`
- Upstream approach: the stage objects (+8 texture, +0 filter mode), their state caches (the sampler banks `00e8_90c0` sets), the passes' render state blocks and Group C's constant entries are live guest state, written by the draw's pass begins and by main's alike
- Fork approach: the cut takes them as own blocks (`statics::take_pass_state`, `take_pass_objects`), the typed readers and writers go through the packet's accessors, the leaf `set_state_slot` and the untyped stage setters of the lighting 3.0 family go through `engine_core::own_view::own_read` and `own_write` (the draw family's accessors, installed when a packet first opens); three readers of the shader objects' counted maps and Group C's bone switch that read guest memory (`skin`, `lighting30`) are read through the packet
- Side effect: the stepped draw thread's stream with the three readers fixed differs from the one before (commands 29920 on): the serial stream's draw state is the new one's, the old stream bound a texture and sent bone constants the serial run does not
- Decision: keep; offer upstream
- Reason: nv-rs#992 (part of #938): the joins of the sun query and the extra passes can go only when this state is the draw's own
- Evidence: `the_cut_takes_the_pass_objects_and_group_c_entries`, `the_draw_reads_the_pass_objects_as_cut_while_main_begins_the_same_pass` (crates/engine/tests/draw_pass_state.rs); the recorded-run gate in docs/FIXES.md
