### per-draw invariants
- Files: `crates/engine-core/src/engine.rs` (the engine number in the probe key), `crates/engine-core/src/real_threads.rs` (`DeviceHalf`, the geometry-half counter and the probe counters), `crates/engine-platform/src/d3d9device.rs` (the device-half's call-order and probe test), `crates/engine-typed/src/render/draw.rs`, `crates/engine-typed/src/draw/packed.rs`, `crates/engine-typed/src/shader/batch.rs`
- Upstream approach: each strip of a packed geometry re-reads its length, base vertex, vertex count and kind; each of the draw paths runs the renderer's skinned test again, including its guest virtuals; every device call probes the world draw's device-lock half (nv-rs#935).
- Fork approach: the strip loops read their words once before they begin, the skinned test's answer is kept for a renderer, target, their vtable pointers and the memory words it reads, and one geometry's device calls share one hold of the device lock. A nested geometry reuses the outer hold. The original re-reads `strips`, `lengths`, `fallback`, `vertices`, `base` and `kind` for each strip or partition; the fork hoists them because a strip's draws change none of those words, while `geometry_slot_word` and the device calls stay in the original order. Every call the original makes is still made, in the same order; a cache hit saves only a repeated probe.
- Decision: keep, offer back when upstream takes the same per-draw work off the main thread.
- Reason: the draw path is about 40% of the game main thread and the device thread waits for it (docs/fork/PERF.md); these are per-draw costs that do not change what is drawn.
- Evidence: the typed families' differential cases for `draw_packed`, `draw_shape`, `draw_partition`, `is_skinned` and `render_pass`, the skinned-probe unit test in `render/draw.rs` (word, renderer vtable and target vtable changes are re-probed, two renderers get different slots), and the device-half tests in `engine-core`'s direct tests (a nested begin keeps the outer hold with a waiter) and `engine-platform`'s device tests (calls made in order under a held lock). The record-stream, pixel and `NV_PERF` ABBA gates were not run here and stay with the maintainer.
