### Loader and garbage collector jobs
- Files: `crates/engine-core/src/lib.rs`, `crates/engine-core/src/real_threads.rs`, `crates/host/src/fixes.rs`, `crates/game-profile/src/game_ini.rs`, `crates/engine-fallout-misc/src/units/fallout_misc/main.rs`
- Upstream approach: `Main::OnIdle` calls `00c3dbf0` (the IO manager's queue, which includes the model loader's walk), `00868850` and `00868d10` with `e.call` on the game thread. Checked at those three call sites in `Main::OnIdle` (`fn_0086e650`; the queue's one word is the `0x01202d98` global; the two collector calls follow the `00a61cd0` call and are not conditional); the loader's locks are guest locks taken by the translated functions.
- Fork approach: the three calls go through `engine_core::loader_jobs`. With stepped threads and `NV_LOADER_JOBS=1`, each is posted to the stepped component helper (shared with Havok's step, one job at a time) and joined before the next game call, with the poster's thread id, TLS values, x87 control word and virtual clock, so the guest locks keep their owner and order and the join ends the uploads before the draw. `NV_LOADER_JOBS` is one of the host's test variables (`fixes::TEST_VARIABLES`, `game_ini::TEST_SWITCHES`, one line each), so a run that sets it is a test run and play never has it on silently. The jobs use the Havok helper, not the scene helper's slot (`SCENE_SLOT`), and the helper area's layout (pool, scene, Havok, drawing) is unchanged: no slot is taken. With real threads, a diagnostic, a dual typed family, a busy helper or the default switch off, the call stays inline.
- Decision: keep; drop when upstream provides its own loader and garbage collector job seam
- Reason: nv-rs#941 moves the loader's per-frame work and the garbage collection pass off the game thread without changing the reference path; ADR-0015 keeps real threads off until the race campaign passes
- Evidence: `crates/engine-core/tests/loader_job_stepped.rs` compares the two paths' calls, words, control word, rounded f32 store, stop text and call stack, checks that the jobs run on a helper OS thread other than the poster's, that a posted job keeps the helper so the next call runs inline before its join, that no job is left posted at the draw, that a diagnostic keeps the call inline, and that the loader and Havok steps share the one stepped helper thread; it uses stand-ins and scratch memory made in the test. The stepped recording comparison, the race campaign and the cell-border and loading hitch measurements are left to the maintainer with the commands and record table in `docs/fork/LOADER-JOBS.md`; no game runs were available here
