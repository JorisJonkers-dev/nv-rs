### The pass begins' shared state is in the detached draw's value packet
- Files: `crates/engine-core/src/own_view.rs`, `crates/engine-typed/src/draw/capture.rs`, `crates/engine-typed/src/draw/cut.rs`, `crates/engine-typed/src/draw/own.rs`, `crates/engine-typed/src/draw/statics.rs`, `crates/engine-typed/src/shader/constants.rs`, `crates/engine-typed/src/shader/geometry.rs`, `crates/engine-bs/src/units/bsshader/run_00c02ce0.rs`, `crates/engine-fallout-unplaced-b/src/units/unplaced/run_00a5f860.rs`, `crates/engine-havok/src/units/bshavok/bhkworld.rs`
- Upstream approach: the 22 vertex and 22 pixel constant entries' enabled byte (+8) and switch word (+0x20) and the shader objects' counted pointers (+0x28, +0x30, +0x34) are live guest state, written by the draw's pass begins and by main's (`00c02ce0`, `00c02f70`, `00a5f860`, `00c663d0`) alike
- Fork approach: the cut takes them as own blocks (the counted pointers marked counted, their objects held), the draw's accessors keep them in the packet, and the translations of main's writers say what they wrote (`engine_core::own_view::note_write`, answered by `capture::note_write` for the addresses a packet owns) so that the join keeps main's value where main wrote last, also an equal one; the counts follow the serial order at the join
- Decision: keep; offer upstream
- Reason: nv-rs#992 (part of #938): the joins of the sun query and the extra passes can go only when this state is the draw's own; this step adds the blocks with the joins kept
- Evidence: `main_wins_the_pass_state_it_wrote_last_and_the_counts_follow` and `the_draws_pass_state_stands_when_main_writes_nothing` (crates/engine/tests/draw_pass_state.rs)
