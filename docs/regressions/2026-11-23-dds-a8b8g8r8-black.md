# DDS textures in A8B8G8R8 drew black

- Issue: nv-rs#823
- Since: the texture loading of `d3dx-tex` replaced D3DX on Linux; the format was never read there
- Cause: D3DX's table names A8B8G8R8 and X8B8G8R8, but `d3dx-tex` had no row decoder or encoder for them, so the create call answered `NotProvided` and no DLL could answer on Linux.
- Why it was not caught: the game's own archives have no file in these formats, and the synthetic format set did not include them.
- Tests: `an_a8b8g8r8_file_makes_the_texture_of_the_same_colours`, `an_x8b8g8r8_file_makes_the_opaque_texture_of_the_same_colours`, `every_channel_value_survives_every_dither_threshold`, `a_device_that_takes_a8b8g8r8_keeps_it_with_the_same_colours`, `a_device_that_takes_x8b8g8r8_keeps_it_with_the_same_colours` (`crates/d3dx-tex/tests/fork_abgr.rs`)
